## 0.1.0 (2026-11-15)

### Added

- Add the shared JSONL reader and writer with explicit reporting for torn and damaged lines. Add typed proxy ledger rows with parsing, status classification, sequence gap detection, and trial filtering. ([#10](https://github.com/wd7512/harbor-research-runner/issues/10))
- Add strict records and parsers for run metadata, run events, resource samples, machine checks, trial evidence, limits, and proxy control messages. Persist machine checks with atomic writes, and publish run metadata once by linking the temporary file into place so an existing record is never replaced. ([#11](https://github.com/wd7512/harbor-research-runner/issues/11))
- Add validated job file parsing and task-major slot planning. Add packaged model cards converted to the runner schema and a loader for packaged or extra cards. ([#12](https://github.com/wd7512/harbor-research-runner/issues/12))
- Add the trial validity verdict with canonical proxy-ledger row validation, physical bad-line attribution and the per-trial labels and measurement reasons. ([#13](https://github.com/wd7512/harbor-research-runner/issues/13))
- Add the run halt rules: quota exhaustion, proxy-invalid streaks, the zero-billed window, dead proxy or sampler, sustained host breach and inactivity, evaluated in the contract's order. ([#14](https://github.com/wd7512/harbor-research-runner/issues/14))
- Add pure statistics functions for trial views, pass rates, paired comparisons, costs, and completeness.
  Use the model card's per-million input, cache-read, and output rates to estimate cost. ([#15](https://github.com/wd7512/harbor-research-runner/issues/15))
- Add a thread-safe proxy ledger writer that resumes sequence numbers from parseable rows, separates a torn tail before appending, and assigns timestamps as it writes. A background sync thread periodically fsyncs and makes close rows durable without holding the write lock. ([#21](https://github.com/wd7512/harbor-research-runner/issues/21))
- Add the chat relay core: forward nonterminal raw upstream stream bytes immediately, observe every event through the terminator, and record request start and end rows with final usage, character counts and byte-rooted monotonic timing. Every relayed response owns its upstream connection and releases it when the response or its chunk iterator is closed. ([#22](https://github.com/wd7512/harbor-research-runner/issues/22))
- Classify every relayed request with one upstream status, port the 429 quota rules, and cut first-chunk, inter-chunk-gap and total-latency stalls while preserving upstream error bodies and Retry-After. ([#23](https://github.com/wd7512/harbor-research-runner/issues/23))
- Add the proxy trial registry: replay open and closed trial identities from the ledger, refuse closed or unopened trials, and expose a fresh `LedgerWriter.history()` snapshot so a restarted proxy keeps its decisions. Registry calls now fail when the ledger is unavailable, and replay rejects history that does not begin at sequence 1. ([#24](https://github.com/wd7512/harbor-research-runner/issues/24))
- Add in-memory, thread-safe rolling-window pacing shared across requests, with prompt-token estimates and restart cool-down support. Actual token counts replace pending estimates in FIFO order. ([#25](https://github.com/wd7512/harbor-research-runner/issues/25))
- Model requests now rotate across model-card keys and endpoints, and retry eligible upstream failures on the next route before any response reaches the harness. The proxy records absorbed failovers in the request end row. ([#26](https://github.com/wd7512/harbor-research-runner/issues/26))
- Add chat and Responses API adapter translations, including preservation of `store` and prompt character counts for tool history. ([#27](https://github.com/wd7512/harbor-research-runner/issues/27))
- The model proxy can retain each trial's raw request and response bodies in deterministic gzip-compressed JSONL files. Body storage failures are logged and do not interrupt requests. ([#28](https://github.com/wd7512/harbor-research-runner/issues/28))
- Add a standalone model proxy process with control and trial routes, adapter-based relaying, restart-aware ledger startup, graceful shutdown, pacing, and request body persistence. Unsupported API pairs return 400 without a ledger row, and unknown paths return 404. ([#29](https://github.com/wd7512/harbor-research-runner/issues/29))
- Add a fail-closed harness commit manifest that verifies architecture-specific local image digests. Manifest updates preserve existing entries and write atomically. ([#30](https://github.com/wd7512/harbor-research-runner/issues/30))
- Extract the harness files from a pinned image on the host into a digest-keyed cache under the caller's workdir, refusing an image whose `opencode` binary is missing or empty; `cleanup` never removes an extracted tree or any part of it. Docker create, copy and remove calls use the fixed 600-second timeout. ([#31](https://github.com/wd7512/harbor-research-runner/issues/31))
- Add `harness/opencode_eras.py`: plain functions that classify an OpenCode version, probe advertised flags, render the era's config files, and build the run command. The config pins sampling, restores the 1.x variant map and 2.x variant list with default folding, uses the trial-scoped proxy URL verbatim, and writes no `x-trial-id` header. ([#32](https://github.com/wd7512/harbor-research-runner/issues/32))

Agent settings round trip the embedded model card and variant, are accepted by Harbor's preflight and construction, and run config, skills and the agent command with OpenCode's fixed `OPENCODE_FAKE_VCS` and XDG environment. ([#33](https://github.com/wd7512/harbor-research-runner/issues/33))

Record the exception timestamp in trial facts and use the same phase calculation for verdict labels and agent exit details. ([#40](https://github.com/wd7512/harbor-research-runner/issues/40))
- Fixed run startup wiring so host metadata, machine checks, and host lock refusals are recorded correctly. Docker cleanup now logs planned, skipped, and removed resource names. ([#56](https://github.com/wd7512/harbor-research-runner/issues/56))
- CLI path arguments now become absolute when parsed, including relative defaults, so Harbor subprocesses resolve them consistently from their working directories. The machine-check e2e fixture uses the local task folder name recorded by the runner, and the detached-heartbeat test matches Python's `-c` argument without mistaking worktree paths for it. ([#75](https://github.com/wd7512/harbor-research-runner/issues/75))
- Raised the listen backlog to 128 for the model proxy, results explorer and fake upstream server to handle bursts of concurrent connections. Moved the source tree import-rule scan to the integration tier while sharing its checker with the unit tests. ([#78](https://github.com/wd7512/harbor-research-runner/issues/78))
- Machine checks now record and exclude tasks that fail during environment setup, while preserving the existing errors for incomplete trials that fail later. When no task is included after setup failures, the check reports each setup error. ([#102](https://github.com/wd7512/harbor-research-runner/issues/102))
- Launch and resume checks now recompute selected local task hashes with Harbor's task packager and refuse when task content has changed since the machine check. The refusal names affected tasks and asks for a new machine check. ([#109](https://github.com/wd7512/harbor-research-runner/issues/109))
- Pacing corrections now update the reservation owned by each request, so out-of-order completions cannot shift actual token usage between requests. The relay carries the reservation through completion and ledger failure handling. ([#109](https://github.com/wd7512/harbor-research-runner/issues/109))
- A finished trial with an open ledger row but no close row is now marked unmeasured. This prevents a missing proxy close from counting toward run completion.
- A run now keeps a write-once copy of its machine check as `machine-check.json` in the run folder, from the same bytes whose SHA-256 is in `run-metadata.json`, so `hrr build-evidence` finds it.
- A run that finishes after a halt on Linux Docker Engine no longer crashes on files a container wrote as another user; they are left as found and named in the run log.
- Classify upstream 401, 402 and 403 responses as `upstream_auth`, count them against trial validity and allow failover. Document the status in the proxy ledger contract.
- Explorer comparisons now use only the selected arm from each selected evidence bundle. The comparison table and paired result use the same selected observations.
- Harbor failures that leave planned trials unlaunched now halt runs resumably instead of finishing them. The halt records the Harbor exit code, and the pass loop and resume path share the same remaining-trials check.
- Harness image builds and version checks use the host network when Docker has no bridge network. Bridge-enabled hosts keep the existing Docker commands.
- Host swap limits now detect pages swapped out during each sampling interval, so stale occupied swap no longer blocks launch or invalidates work. The resource and limits readers retain compatibility with older records.
- Machine checks record each task image's architecture, and launch checks verify arm images for every task architecture used by the run and the canary. Older machine checks continue to fall back to the Docker host architecture.
- Model cards can declare upstream headers and a per-run session header. OpenCode Go now receives a stable session ID and its required User-Agent, while OpenRouter receives its identifying headers.
- Model cards for OpenCode Go and OpenRouter list one key variable each (`OPENCODE_GO_API_KEY`, `OPENROUTER_API_KEY`); the second name was an alias in the old tool, but here every listed name is a required failover key, so runs refused unless both were set.
- Non-streaming proxy responses now wait for the complete upstream body before choosing the harness status. Stalls and transport failures return retryable errors whose status matches the proxy ledger.
- On a host without a bridge network, the overlay now also sets `build.network: host` when `tasks.images: build`, so BuildKit's `RUN` steps no longer fail with `network bridge not found`.
- Pin development tools v0.2.1 so the layout check detects source files whose mirrored tests are missing. The placeholder CLI is explicitly exempt until its command implementation lands.
- Proxy startup replays the valid rows after torn or unparseable ledger lines and logs their locations. Trial verdicts remain responsible for marking affected records unmeasured.
- Refuse to resume runs that stopped before their first main Harbor pass, preserving the run folder for inspection and directing the operator to start a new run.
- Reset the upstream invalid streak window after each resume, so failures from an earlier pass do not halt the resumed run. Historical verdicts remain in the event log for judging and evidence.
- Resolve relative local task paths against the job file when parsing it. Generated Harbor configs and resumed runs now keep the absolute task location.
- Resume events now record the active runner's version and commit while preserving the launch metadata unchanged.
- Slowest-first task ordering now reads Git task timeouts from Harbor's downloaded task folder. Local task paths keep their existing resolution behavior.
- Streamed chat requests routed to a Responses API now record cached input tokens from the normalized usage callback. This keeps cached token totals available to evidence and cost estimates.
- The 2.x arm passed `--model` before `run`, which OpenCode 2.2.7 rejects.
- The canary now asks Harbor for its task by folder name, the name Harbor filters local tasks by, so a run no longer aborts at the canary.
- The memory watchdog now matches `docker stats` rows by full ID, short ID or name. Without a container argument, Docker puts the full ID in `Container`, so on kernel-capped hosts the watcher recorded and enforced nothing.
- The memory watcher retries transient Docker listing and stats failures. It exits after 30 consecutive failed samples so a persistent Docker outage still halts the run.
- The proxy now checks trial admission and records `request_start` under the same lock after pacing, so a request waiting when its trial closes is refused before reaching upstream.
- The results explorer no longer does a reverse DNS lookup of its bind address at startup, which stalled about 35 s on hosts with slow reverse DNS; it now shares one loopback server base with the model proxy.
- The trial pane now prints a Harbor view command for the entered run folder and identifies the job and trial to open.
- Trials blocked at the launch deadline are recorded and reported as deferred. Deferred set-asides do not consume a slot's invalid set-aside budget.
